## 1. 目标

在本地观察 OpenCode 自己发出的 HTTP 请求，用于：

- 查看最终 URL、HTTP method、header、body 结构；
- 查看模型、`stream`、tools 等关键字段；
- 排查 provider 配置、网络和协议兼容问题；
- 保存脱敏后的请求元数据，便于分析。

本方案只用于调试自己有权访问的 OpenCode 实例和上游，不用于绕过第三方服务的访问控制。

## 2. 组成

```text
opencode-proxy/
├── package.json      # 无第三方依赖的 Node.js 项目
├── proxy.js          # 本地 HTTP 转发与日志代理
├── scripts/
│   ├── generate-cert.ps1  # 本地 CA 与服务器证书生成
│   ├── start-proxy.ps1    # 配置环境并启动代理
│   ├── start-opencode.ps1 # 配置代理环境并启动 opencode
│   └── experiments/       # 一次性判别/差分/重放实验脚本（保留归档）
├── docs/             # 设计与逆向分析文档（方案 / 参数手册 / 分析 / 过程总账）
├── README.md         # 使用说明
└── .gitignore
```

`proxy.js` 提供两种能力：

1. **反向代理模式**：把收到的请求转发到 `TARGET_BASE_URL`；
2. **标准代理模式**：作为 `HTTP_PROXY`/`HTTPS_PROXY` 接收普通 HTTP 请求和 `CONNECT` 隧道。

## 3. 配置

环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8787` | 本地监听端口，只绑定 `127.0.0.1` |
| `HTTPS_PORT` | `0` | 可选 HTTPS 反向代理端口；`0` 表示禁用 |
| `TLS_KEY_FILE` | 空 | HTTPS 监听使用的 PEM 私钥 |
| `TLS_CERT_FILE` | 空 | HTTPS 监听使用的 PEM 证书 |
| `TARGET_BASE_URL` | `https://opencode.ai` | 反向代理目标 |
| `LOG_BODY` | `false` | 是否记录 body 预览 |
| `MAX_BODY_LOG_BYTES` | `16384` | body 预览上限 |
| `MAX_PREVIEW_CHARS` | `4000` | 文本预览字符上限 |
| `UPSTREAM_TIMEOUT_MS` | `60000` | 上游超时 |
| `LOG_FILE` | 空 | 追加写入的 JSON Lines 日志文件；空表示只输出到终端 |
| `LOG_SENSITIVE_HEADERS` | `false` | 为 `true` 时不脱敏，明文记录 `authorization`、`cookie`、`x-api-key` 等敏感 header。仅用于本机学习/调试，日志可能包含 API key，开启后请勿外发日志 |

### 3.1 启动脚本

`scripts/start-proxy.ps1`：

- 证书缺失时自动调用 `generate-cert.ps1`；
- 设置 `PORT`、`HTTPS_PORT`、`TARGET_BASE_URL`、`LOG_FILE`、`TLS_*`；
- 清除代理进程自身的 `HTTP_PROXY`/`HTTPS_PROXY`，避免回环；
- 前台运行 `proxy.js`，`Ctrl+C` 停止。

`scripts/start-opencode.ps1`：

- 启动前检查 `http://127.0.0.1:<PROXY_PORT>/__proxy/health`，未运行则退出码 1；
- 设置 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`；
- 存在本地 CA 时设置 `NODE_EXTRA_CA_CERTS`；
- 不声明 `param` 块，所有入参通过 `$args` 原样透传给 `opencode`。

启动：

```powershell
$env:TARGET_BASE_URL = "https://opencode.ai"
$env:PORT = "8787"
npm start
```

健康检查：

```powershell
curl http://127.0.0.1:8787/__proxy/health
```

## 4. 推荐用法

### 4.1 反向代理观测

如果 OpenCode 或测试工具允许配置 provider 的 base URL，将目标指向：

```text
http://127.0.0.1:8787
```

代理会把 `/...` 路径转发到 `TARGET_BASE_URL`。

例如：

```powershell
$env:TARGET_BASE_URL = "https://opencode.ai"
node proxy.js
```

请求：

```powershell
curl http://127.0.0.1:8787/zen/v1/models
```

代理日志会记录目标 URL、脱敏 header，以及 JSON body 中的 `model`、`stream`、`messages`、`tools` 摘要。

### 4.2 标准 HTTP 代理观测

可以让 OpenCode 使用标准代理环境变量：

```powershell
$env:HTTP_PROXY = "http://127.0.0.1:8787"
$env:HTTPS_PROXY = "http://127.0.0.1:8787"
$env:NO_PROXY = "localhost,127.0.0.1"
```

注意：

- `NO_PROXY` 必须包含本地地址，否则 TUI 与本地 server 之间可能形成代理循环；
- 对普通 HTTP 请求，代理可以看到完整 header 和 body；
- 对 HTTPS 请求，代理只处理 `CONNECT`，日志只记录目标主机和端口，不检查 TLS 内部内容。

若必须查看 HTTPS 内部明文，应使用 mitmproxy、Charles 或 Fiddler 等成熟的 TLS 中间人调试工具，并仅在自己的调试环境中安装其 CA。

### 4.3 本地证书与 HTTPS 反向代理

生成本机调试证书：

```powershell
npm run cert
```

该脚本生成：

- `certs/ca.pem`：本地 CA；
- `certs/server.crt`：服务器证书；
- `certs/server.key`：服务器私钥。

启动 HTTPS 反向代理：

```powershell
$env:HTTPS_PORT = "8788"
$env:TLS_KEY_FILE = "E:\projects\ai\opencode-proxy\certs\server.key"
$env:TLS_CERT_FILE = "E:\projects\ai\opencode-proxy\certs\server.crt"
$env:TARGET_BASE_URL = "https://opencode.ai"
node proxy.js
```

用 CA 验证：

```powershell
curl --cacert E:\projects\ai\opencode-proxy\certs\ca.pem https://127.0.0.1:8788/__proxy/health
```

若报 `schannel: the revocation status is unknown`，说明 Schannel 无法对本地 CA 做吊销检查（本地 CA 没有 CRL/OCSP），证书链本身没有问题。仅本机调试可加 `--ssl-no-revoke` 跳过吊销检查；访问外部服务时不要使用该参数。

Windows `curl` 若使用 Schannel 并提示本地 CA “吊销状态未知”，不代表证书链错误；可用 Node.js 传入 `ca: fs.readFileSync('certs/ca.pem')` 做严格验证。

Node.js 客户端信任本地 CA：

```powershell
$env:NODE_EXTRA_CA_CERTS = "E:\projects\ai\opencode-proxy\certs\ca.pem"
```

说明：

- `HTTPS_PORT` 是本代理自己的 TLS 终止端点；
- 标准 `CONNECT` 隧道仍不解密 HTTPS；
- `server.key` 只能留在本机，不能提交到版本库或发送给他人。

## 5. 日志与脱敏

默认不记录 body 内容，只记录：

- body 字节数；
- JSON 中的 `model`；
- `stream`；
- `messages` 数量；
- `tools` 名称列表。

以下 header 会自动替换为 `[redacted]`：

- `Authorization`
- `Proxy-Authorization`
- `X-Api-Key`
- `Api-Key`
- `Cookie`
- `Set-Cookie`

开启 body 预览：

```powershell
$env:LOG_BODY = "true"
$env:MAX_PREVIEW_CHARS = "4000"
$env:LOG_SENSITIVE_HEADERS = "true"
node proxy.js
```

即使开启 body 预览，也应在分享日志前再次检查是否包含密钥、个人信息或私有代码。

## 6. 数据保存位置

### 6.1 本代理

不设置 `LOG_FILE` 时只输出到终端；设置后追加写入指定文件：

```powershell
$env:LOG_FILE = "E:\projects\ai\opencode-proxy\proxy.log"
node proxy.js
```

### 6.2 OpenCode 自身

```text
%USERPROFILE%\.local\share\opencode\log\          # 运行日志
%USERPROFILE%\.local\share\opencode\storage\      # session/ message/ project/ 等
%USERPROFILE%\.local\share\opencode\opencode.db   # SQLite 数据库
%USERPROFILE%\.local\share\opencode\auth.json     # 凭据，含 API key
```

OpenCode 保存的是会话消息和运行日志，**不会**保存最终发出的原始 HTTP 请求 header/body。原始请求需要通过本代理或抓包获得。

## 7. 源码追踪位置

要进一步确认 OpenCode 在发出请求前做了什么，可参考官方源码：

```text
packages/opencode/src/session/llm/request.ts

packages/opencode/src/provider/transform.ts
```

重点观察：

1. `LLMRequest` 构造阶段；

3. HTTP client 最终发出的请求；
4. `stream`、tools 和 provider 特有字段的变化。

基于本代理抓包做的判别实验与完整结论（`x-opencode-session` 生成算法、上游免费额度准入规则）见 [分析-会话标识与免费额度校验.md](./分析-会话标识与免费额度校验.md)。

## 8. 边界与限制

- 本代理是简单的本地调试工具，不是生产网关；
- 默认只监听 `127.0.0.1`；
- 请求 body 超过 32MB 会拒绝，避免调试时占用过多内存；
- 对 SSE/流式响应直接透传，不缓存完整响应；
- `CONNECT` 是盲隧道，不解密 HTTPS；
- HTTPS 反向代理仅在显式配置 `HTTPS_PORT`、`TLS_KEY_FILE`、`TLS_CERT_FILE` 时启用；
- 不实现、不注入任何第三方服务的客户端指纹或访问绕过逻辑。

## 9. 合规说明

该代理适合用于：

- 调试自己的 OpenCode 配置；
- 验证自己实现的 API 兼容性；
- 分析自己拥有的网络流量。

不适合用于：

- 伪造第三方客户端身份；
- 绕过 free-tier、区域、配额或授权限制；
- 收集、传播他人的凭据或私有请求数据。
