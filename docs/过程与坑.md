# 逆向全过程记录：时间线、踩坑与成功请求要求

> 本文是整个"抓包 → 源码逆向 → 判别实验 → 代理实现"过程的**总账**：记录做了什么、每一步的证据、踩过哪些坑，以及最终结论——**opencode 上游对一个成功请求到底要求什么**。
> 细节证据不在本文重复展开，均交叉引用到专项文档（分析 / 请求参数 / verify-go / proxy-go）。
>
> 端点：`https://opencode.ai/zen/v1/chat/completions`（匿名免费额度，`authorization: Bearer public`）。
> 基线：opencode monorepo `545f51d`（v1.18.32）；实验日期 2026-09-21 ~ 2026-09-22。

## 二、时间线（每步证据编号）

证据编号约定：**P1~P24** = header 维度单变量判别针（矩阵见分析文档 §4）；**T1~T11** = body 维度单变量判别针（见分析文档 §5.2）。失败针不产生费用，每针对照一条全新合法 ID。

### 阶段 1：抓包建立基线

- 本地反代观测 opencode 客户端的真实出站请求，拿到**未篡改的完整 payload**（2467B，含真实 system 模板）与**真实 SSE 响应**（`resp-body.sse`）。见 [方案.md](./方案.md)、分析文档 §9 证据文件清单。
- 关键教训起点：OpenCode 自身**不保存**最终发出的原始 header/body（根 README「文档」节上方说明），不抓包就只能猜。

### 阶段 2：源码提取客户端 ID 算法（源码级结论）

- 在 opencode monorepo 定位 `packages/schema/src/identifier.ts`（全文 30 行）：`ses_` = 12 位 hex 时间戳（**降序**排列）+ 14 位 `[0-9A-Za-z]` 随机段；`msg_` 同结构但时间戳**正序**。
- 复刻生成器与抓包实测 ID **逐字节对拍吻合**。见分析文档 §1、请求参数 §4.1。

### 阶段 3：24 针 header 判别实验（门① 门② 闭环）

- 单变量法：固定抓包原 payload，每次只改一个 header，观察 200/403/426。矩阵与结论见分析文档 §4：
  - **门①**：`x-opencode-session` 匹配 `^ses_[0-9a-f]{12}[0-9A-Za-z]{14}$`，否则 403（P 系列 session 维度 11 针）；
  - **门②**：`User-Agent` 需以**子串、大小写不敏感**方式解析出 `opencode/<semver>` 且 `>= 1.18.0`——解析失败 403、版本过低 426（P17/P18 边界针，P21/P22/P24 宽松针）；
  - **顺序**：session 校验先于 UA 校验（P23）；
  - **不校验**：提前注册（P1）、时间新鲜度（P3，3.58 天前的时间戳照样 200）、时间一致性（P2）、`x-opencode-client`（P9）、`x-opencode-project`（P19）、`x-opencode-request` 存在性（P15 省略仍 200）。

### 阶段 4：文档化与离线验证

- [请求参数与Header说明.md](./请求参数与Header说明.md)：11 个实捕 header 全量清单、body 顶层字段、`msg_` 三层唯一性保障、响应侧 usage/cost/限流（§8）。
- [verify-go/](../verify-go/README.md)：把 24 针结论做成离线证据表比对程序，防止后续改动破坏结论。

### 阶段 5：proxy-go 代理实现

- 功能（详见 [proxy-go/README.md](../proxy-go/README.md)）：
  - 任意 `x-session-id` → 稳定映射同一条上游 `ses_`（内存 + SQLite `session_map`，重启不变）；`x-message-id` 分域稳定映射（`message_map`）；
  - header 重写：注入 UA / `authorization: Bearer public` / `x-opencode-*`，丢弃客户端伪造的同名头；
  - 非流式调用方由 `translate.go` 把上游 SSE 组装回 `chat.completion` JSON；
  - 每请求落 `request_log` 审计。
- 质量门全绿：`gofmt` / `go vet` / `go test ./...`（含假上游 e2e、真实 `resp-body.sse` fixture：usage total=594、cost=0、finish=length）。

### 阶段 6：冒烟 403 → 门③ 被逼出来（T1~T11）

- 用极简 body（无 system、无 stream）+ 合法 header 冒烟真实端点 → **首测 403**，与"header 双门已闭环"矛盾。单变量收敛后闭环（表见分析文档 §5.2）：

| 针 | body 变量 | 结果 |
|---|---|---|
| T1 | 抓包原 payload（仅改 max_tokens） | **200** |
| T3 / T4 | 无 system / 短 system | 403 |
| T5 / T9 | system 填充 `x*3000` / `y*2100`（长度假设） | 403（长度无关，假设证伪） |
| T8 | 真模板 + 任意 user 内容 | **200** |
| T10 | 真模板但缺 `stream:true` | 403 |
| T11 | 真模板 + 仅补 `stream:true`（去掉 temperature/stream_options） | **200** |

- 结论：**门③ = body 并列两条件**——首条 system 含真实 opencode 模板内容 **且** `"stream": true`，缺一 403。

### 阶段 7：门③ 修复与真实端到端 200

- `proxy-go/fixup.go`：`inject_template` 模式做**保序字节拼接**（json.Decoder token 走查 + RawMessage，role 在前）注入模板 + 顶层强制 `stream:true`；对原本非流式的调用方，`translate.go` 把 SSE 组装回 JSON。
- 真实 E2E 坐实：极简非流式 body + `x-session-id: final-verify-1` → **HTTP 200**，返回 JSON（usage/cost/reasoning 齐全）；同会话两连发映射同一 `ses_`（hits=2），`session_map` / `request_log` 落库确认。
- 代理运行在 `127.0.0.1:8790`（8788 被占用，`-listen` 覆盖；默认 8788）。

### 阶段 8：aicli 接入判别（G/H 系列）：门⑤ 身份头组、门⑥ 工具面白名单、reasoning_effort 值域

> 触发：aicli 经本地代理调上游 403/500。单变量实测（`scripts/experiments/replay/` 下的 `run-g-tests.py`、`run-h-*.py`、`run-precision*.py`、`run-effort-values*.py`）定位到 P/T 系列未覆盖的两道新门与一个 500 雷，完整表见 [分析-会话标识与免费额度校验.md](./分析-会话标识与免费额度校验.md) §5.3：

- **门⑤ 身份头组**：不带 UA `opencode/<ver>…` + `x-opencode-*` 四头 → **任何 body 一律 403**（G1/G2d/H1/H5）；带齐即 200（G6 两次复现）。值无需真实有效（代理注入的编造 session 值 T13 也 200）→ "现场 200 = opencode TUI 自带真头"的解释。
- **门⑥ 工具面白名单**：tools 必须是 opencode 真实工具 schema 且 **≥ 2 个**（H17=2 个 → 200、H15=6 个 → 200、H13=12 个 → 200；H16=1 个 → 403；46 个 aicli 自有工具 → 403）。
- **500 雷 = `reasoning_effort:"max"`**：H10 与 G1 深度 diff 唯一差异即该字段（`scripts/experiments/replay/verify-g1-h10.py`）；值域实验（`scripts/experiments/replay/run-effort-values*.py`）→ 上游只认 `{none, low, medium, high}`，`max`/`minimal`/`xhigh`/非法值全 500。协议角度 `max` 是 OpenAI 官方合法值（官方 SDK 类型为证，见 [请求参数与Header说明.md](./请求参数与Header说明.md) §3.3），500 是**取值超出该模型后端支持面**。
- **门③ 修正**：H13/H14（aicli env-context system，无 opencode 模板）→ 均 200——带完整身份头组合下 system 内容不参与准入；"system 模板必需"（H-A）只在无完整身份头条件下成立。
- **修复建议**：aicli 侧 tools 换成 opencode 真实 12 工具 schema + `reasoning_effort: "max" → "high"/"medium"`；或由代理层做工具面重写 + effort 值降级映射（`max/xhigh → high`、`minimal → low`）。

## 三、踩坑清单

每条附复现/证据与规避方法。这是本文最有"含金量"的部分——多数坑都曾导致**错误结论**。

### 坑 1：'仅 header 决定准入'结论过窄（最贵的一个坑）

- **现象**：24 针 header 针全绿（verify-go 复算一致），但真实冒烟用极简 body 首测 403。
- **归因**：P 系列实验全程**固定 2467B 抓包 payload**，body 是隐含常量；结论"通过/拒绝 100% 由 header 解释"只在固定 body 之上成立。
- **修复**：T1~T11 补 body 单变量，逼出门③；分析文档 §0/§5.2/§7② 与请求参数 §7 均已收窄改写。
- **规避**：宣称"仅 X 决定"之前，先把所有未变维度显式列成"实验常量"（分析文档 §7 的价值），并至少挑一两个常量做反向判别。

### 坑 2：早期 403 归因错误——不是"注册制"，是格式非法

- **现象**：verify-go 时代多次 403，一度归因为"服务端要求会话预先注册/封锁 curl"。
- **真实原因**：判别针用了伪造值如 `ses_curl_test_001`——随机段含 `_`，**不满足门①正则**，当然 403。
- **规避**：判别针必须用**本地按源码算法新生成的合法 ID** 做对照；403 文案 "free tier can only be used from within OpenCode" 是 UA/session 结构未过的兜底错误，**不是**"客户端真实性验证"（分析文档 §0.5）。

### 坑 3：PowerShell JSON 引号坑

- **现象**：`curl -d '{"model":\"x\"}'` 单引号串里的 `\"` 是**字面量**反斜杠+引号，服务端解析出的 `model` 为空/畸形，请求失败还难以定位。
- **规避**：构造 body 一律用 `python -c` 或临时文件生成，`curl --data-binary @file` 发送；不要在 PowerShell 单引号串里手写转义。

### 坑 4：Go map 序列化 key 字母序 → 门③ 403

- **现象**：代理把模板注入逻辑写成 `map[string]any{"role":…,"content":…}` 后 `json.Marshal`，输出变 `{"content":…,"role":…}`（**字母序、content 在前**），实测 403。
- **归因**：门③按原始字节/结构匹配，role 必须在前；同时手写测试 SSE 流多一个 `}` 会让解析**静默降级**（finish 停在 stop、tool_calls 空），浪费一轮排查。
- **规避**：`fixup.go` 用 json.Decoder token 走查 + `json.RawMessage` 做**保序字节拼接**；fixture 解析后必须断言关键字段，不能"没报错就算过"。

### 坑 5：Windows 端口占用与文件锁

- **现象**：默认 8788 被本仓 node 进程占用，代理起不来；重建 `proxy-go.exe` 时旧进程未退，构建报文件占用。
- **规避**：`-listen 127.0.0.1:8790` 覆盖端口；重建前 `Get-NetTCPConnection -LocalPort X` 找 PID → `Stop-Process`。

### 坑 6：文件工具的前置条件与精确匹配

- **`append_write` 的 `expected_offset` 过期** → `WRITE_PRECONDITION_FAILED`（报"当前 offset 9621"而请求带的是 9438）：重读文件取当前 offset 再重试，别盲改内容。
- **`multiedit` 部分失败**：只重跑失败项——old_string 必须按工具回显的"最接近内容"精确重建（`- ` 列表项 vs `1.` 编号、中文引号 `“”` vs ASCII 引号 `"` 都算不匹配）。

### 坑 7：判别实验纪律（避免污染与费用）

- 失败针不产生费用，但**每针仍对照一条全新合法 ID**，排除"某个 ID 被服务端记黑"的污染可能；
- 先看抓包 payload 的**顶层字段**再设计单变量（门③的 `stream` 就藏在顶层，最初差点只在 system 内容里打转）；
- 单变量：一次只改一个维度，固定其余全部常量，并把常量清单写进文档（§7），供后续收窄结论。

### 坑 8：zen 资源文件缺失 → 工具面静默降级（症状是上游 403，日志里什么都没有；2026-10-16 已修复）

- **现象**：调用方没带 `read` 工具的请求被上游 403（v2 准入的 tools 项，见 [分析-opencode-v2指纹与准入.md](./分析-opencode-v2指纹与准入.md) §三），但代理日志里**一行提示都没有**——既不报"文件缺失"也不报"未注入"，只能靠 diff 请求体才看得出 tools 与从前不同。
- **根因**：`opencode_tools.json` 原为第三方私有转储、被 `.gitignore` 排除（**2026-10-16 起根目录那份已入库**，见本坑“规避”），`proxy.js` 按 `__dirname` 定位它；加载失败走 `catch → []`（`proxy.js:159-164`），注入处再 `if (readTool)` 静默跳过（`proxy.js:263-266`）。文件一旦不在代理脚本同级目录，"tools 缺 read 时前插 canonical read 工具"就无声失效；而**调用方自带 read 时完全不受影响**（`proxy.js:262`）——同一份配置下时好时坏，极易被误判成上游抖动或调用方 body 问题。
- **两侧行为不对称（本坑的关键，已修）**：`proxy-go` 在启动期就 `slog.Warn("v2 模式未取到 read 工具，缺 read 的请求会被上游 403")`（`proxy-go/server.go:69`）；`proxy.js` 过去**进程内完全静默**，只有 `scripts/start-proxy.ps1` 在启动时黄字提示（`scripts/start-proxy.ps1:100-106`）→ **裸 `node proxy.js` 启动时，这类 403 零提示**。**修复**：`loadZenTools()` 取不到 canonical `read`（文件缺失 / JSON 解析失败 / 顶层非数组 / 无 `read` 条目）时输出一条 `event=zen_tools_missing` 的 warn（`proxy.js:165-176`），带 `toolsFile` 与 `reason` 两个字段，措辞与 Go 侧一致；`zenTools` 有缓存，故每进程至多一条。
- **规避**：根目录 `opencode_tools.json` 现已入库（满足准入的最小版，开箱即用）；若要换成完整真实工具面，把自备转储放到 `<项目根>\opencode_tools.json`（**跟踪**，即基线，适合放满足准入的最小/公开版）或 `<项目根>\proxy-go\opencode_tools.json`（**该位置已被 `.gitignore` 排除**，属本地覆盖、不入库，适合放私有完整转储）。**注意自动定位是「根目录优先」**（`scripts/start-proxy.ps1:60-63`）：根目录那份存在时 `proxy-go\` 那份不会被选中，要用本地覆盖必须显式 `$env:ZEN_TOOLS_FILE=<项目根>\proxy-go\opencode_tools.json`（外部已设值不被覆盖）或先移走根目录那份——即恢复注入——**这是本坑唯一的真正解法**，warn 只负责把故障显形；优先用 `scripts/start-proxy.ps1` 启动（按这两处顺序自动定位并导出 `ZEN_TOOLS_FILE`，外部已设值不覆盖）；排查此类 403 时先看启动输出里有没有 `[proxy] zen  ZEN_TOOLS_FILE = <路径>`、有没有黄字 `未定位到`；修复后进程 stdout 里也会出现 `zen_tools_missing`（`reason` 直接给出缺失原因，不必再 diff 请求体）。
- **附带校准**：v2 下模板注入已废弃，`opencode_system_prompt.txt` / `opencode_agent_system_prompt.txt` 缺失**不影响准入**（`proxy.js` 里对应加载函数与 1.x 的 12 工具规范化函数均已无调用点，仅为兼容旧配置保留）；**只有 `opencode_tools.json` 缺失会真的导致 403**。
- **复验（2026-10-16，n=2）**：影响面比"只影响第三方调用方"更大——**连文档 §四 那条极简 body（不带 `tools`）也 403**，因为准入②的 `read` 本来就是靠注入补的；同一请求补上工具面文件后 `/inference/v1` 与 `/zen/v1` **都 200**（因此顺带勘误了"旧 zen 端点已锁死"，见 §四 复验记录）。**收尾（2026-10-16）**：根目录最小工具面已入库，默认环境（不设 `ZEN_TOOLS_FILE`）下 `compat-final.mjs` 回到 `/inference/v1` 200 / `/zen/v1` 200，前插的 `read` 已从 `fresh-capture.log` 的 `body.preview` 逐字复核。固定回归用例：`scripts/experiments/smoke/verify-zen-tools-warn.mjs`（3 用例 / 10 断言：文件缺失 → warn(文件不存在)+403；含 `read` → 0 warn + 前插 + 200；无 `read` 条目 → warn(canonical 工具面里没有 read 条目)+403）。

### 其他已知小坑

- 工具侧：代码搜索优先 toolkit `grep`（shell `rg` 无匹配退出码 1 会"毒化"串联命令）；无 bash heredoc（PowerShell）；`gh` 不可用（要 GitHub 就走 `git`/API/curl）。

## 四、opencode 对成功请求的完整要求

### 4.1 三扇门（服务端准入，缺一即拒）

| # | 门 | 规则（行为级刻画） | 失败行为 | 证据 |
|---|---|---|---|---|
| ① | 会话 ID 结构 | `x-opencode-session` 匹配 `^ses_[0-9a-f]{12}[0-9A-Za-z]{14}$`（24 针最小等价刻画；时间戳 12 hex **降序**、随机段 14 位 `[0-9A-Za-z]`） | `403` `FreeTierError`：`OpenCode's free tier can only be used from within OpenCode` | P1~P24；算法源码 `identifier.ts`（`ses_` 降序 / `msg_` 正序，`msg_` 不校验） |
| ② | User-Agent 版本 | 子串、**大小写不敏感**解析出 `opencode/<semver>` 且 `>= 1.18.0`（三段可缺省） | 解析失败 `403` 同上文案；版本过低 `426`：`OpenCode 1.18.0 or newer is required to use the free tier` | P17/P18（边界）、P21/P22/P24（宽松）；session 先于 UA（P23） |
| ③ | body 形态 | **并列两条件**：`messages` 首条 system 含**真实 opencode 模板内容**（抓包 title-gen prompt，标记 `You are a title generator`，2096B/落盘 2120B）**且** `"stream": true` | 缺任一 `403`；与大小、user 内容、temperature/stream_options 无关 | T1/T8/T11 → 200；T3/T4/T5/T9 → 403；T10 → 403 |

**门③补充细节**：

- 消息对象必须 **role 在前**（`{"role":"system","content":…}`）；key 字母序/content 在前实测 403——推测按原始字节/结构匹配（坑 4）。
- 模板是全等、前缀还是某个标记（如 `<rules>`）匹配，**未判别**；真实 agent 系统提示词是否同样通过，**未测**（见 §五）。

### 4.2 成功请求的完整构造（可直接用的样板）

**标准 header 组**（成功抓包原值）：

```text
user-agent: opencode/1.18.32 ai-sdk/provider-utils/4.0.23 runtime/bun/1.3.14
authorization: Bearer public
x-opencode-client: cli
x-opencode-project: global
x-opencode-request: msg_0c95d3bd7001ACvWJ22X4KVhfM
x-opencode-session: ses_f369d3bdeffeVp2l2TLH4kB0lY
```

其中只有 `user-agent`、`x-opencode-session` 是硬门槛；`x-opencode-request`/`-client`/`-project` 见 §4.4。`ses_`/`msg_` 用 [verify-go/](../verify-go/README.md) 或 `proxy-go/identifier.go` 按源码算法生成。

**body 必须**：首条 system 含真实模板（或经 proxy-go 自动注入）+ `"stream": true`（或由代理强制并回组 JSON）。

**最省事的用法——经代理**（当前 `127.0.0.1:8790`）：

```powershell
curl http://127.0.0.1:8790/v1/chat/completions `
  -H "x-session-id: 任意值" `
  --data-binary '{"model":"mimo-v2.5-free","messages":[{"role":"user","content":"hi"}]}'
```

三扇门全部由代理补齐（header 重写 + 门③注入 + 非流式回组），调用方只管发标准 OpenAI 请求。

### 4.3 不校验项对照表（明确"不用做"）

| 曾经以为要做的 | 实测 |
|---|---|
| 会话需服务端**预先注册** | 不需要——本地新生成即通过（P1） |
| 时间戳**新鲜度** | 不校验：3.58 天前的时间戳照样 200（P3） |
| ses/msg **时间一致性** | 不校验（P2） |
| 任何**签名/HMAC** | 不存在（无签名字段，改值不报签名错） |
| `x-opencode-request` 必须存在 | 可省略（P15 → 200） |
| `x-opencode-client` | 非必需（P9） |
| `x-opencode-project` | 非必需（P19） |
| `msg_` ID 结构 | 不校验（算法上与 `ses_` 不同序，服务端不看） |

### 4.4 响应用量与限流信息（请求参数 §8 实测）

| 问题 | 答案 |
|---|---|
| token 用量 | **有**：需请求带 `stream_options:{"include_usage":true}`；SSE 尾部/非流式 `usage` 给出 prompt/completion/total + 缓存/推理明细（真实 fixture：total=594，cached=512，reasoning=63） |
| 费用 | **有**：流式 `[DONE]` **之后**追加 `data: {"choices":[],"cost":…}`；非流式为 `json.cost`。免费匿名**恒 `"0"`**；标准 OpenAI 客户端在 `[DONE]` 停止，通常读不到该块 |
| 剩余次数/配额 | **没有**；只在触顶时经错误返回：429 `RateLimitError`/`FreeUsageLimitError`（带 `retry-after` 与文案）等、401 余额/月限/用户限类（请求参数 §8.2） |
| 限流头 | 成功响应被网关响应头白名单清洗，**无** `x-ratelimit-*`（开源网关 `handler.ts` 只放行 `content-type`/`cache-control`） |

代理侧 `request_log` 每请求落库（状态码、耗时、映射后的 `ses_`），可自行累计用量；上游内部 IP/key/TPM 限流参数对客户端不可知（分析文档 §7）。

## 五、边界与未尽项

1. **门③模板匹配形态未判别**：全等 / 前缀 / 特定标记（如 `<rules>`、`You are a title generator`）三者未区分；可用 T8 的真模板做前缀截断实验继续收窄。
2. **真实 agent 系统提示词（带身份头组合下）已闭环**：H13/H14（aicli env-context system，无 opencode 模板）+ 完整身份头 + 12 真工具 → 均 200，system 内容不参与准入（分析文档 §5.3）；"title-gen 模板必需"仅覆盖**不带完整身份头**的组合（门③，T 系列）。
3. **URL 路径与 model 值仍是实验常量**：`/zen/v1/chat/completions`、`mimo-v2.5-free` 全程未变，路径穿越/其它模型值未单列判别（分析文档 §7）。
4. **注入模板的副作用**：代理注入的是"标题生成器"模板，模型作答可能带模板风格；对形态敏感的调用方设 `body_fixup.mode: off` 并自行构造合规 body——但那样极简 body 会 403（门③）。
5. **限流照常生效**：429/401 与代理无关，穿透；闭源网关内部 IP/key/TPM/周月限额参数不可知、不可绕（合规边界见 [方案.md](./方案.md) §9）。
6. **`cost` 语义**：仅付费余额（`billingSource === "balance"`）返回真实美元值；免费匿名恒 `"0"`——不要把它当"额度剩余"读。
