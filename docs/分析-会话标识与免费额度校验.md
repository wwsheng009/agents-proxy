# 分析：x-opencode-session 生成算法与免费额度准入校验

> 状态：结论已闭环（2026-09-22）。客户端生成算法为源码级提取并数值验证；服务端准入规则由 24 针（header）+ T1~T11（body）单变量判别实验推断。
> 版本基线：opencode `v1.18.32`（commit `545f51d`），与本机二进制完全一致。
> 证据产物：`scripts/probe-session.js`、`data/replay/probe-matrix*.json`（详见 §9）。

## 0. 结论摘要

1. **客户端 ID 生成算法 100% 已推断**：源码定义于 `packages/schema/src/identifier.ts`，复刻生成器与实测 ID 逐字节吻合。
2. **服务端免费额度准入 = 三条规则**（伪代码见 §5；门③ 为 2026-09-22 补充）：
   - `x-opencode-session` 必须匹配 `^ses_[0-9a-f]{12}[0-9A-Za-z]{14}$`（否则 `403 FreeTierError`）；
   - `User-Agent` 必须能以**子串、大小写不敏感**方式解析出 `opencode/<semver>`，且版本 `>= 1.18.0`（解析失败 `403`，版本过低 `426 UpgradeRequired`）；
   - **body 形态（门③，T1~T11）**：`messages` 首条 system 含真实 opencode 模板内容 **且** `stream:true`，缺一 `403`；
   - session 校验先于 UA 版本校验（P23 证明）。
3. **不存在**会话注册、签名、时间新鲜度、session/msg 时间相关性校验（P1~P3 直接证伪早期"必须服务端注册"的假设）。
4. `x-opencode-client`、`x-opencode-project`、`x-opencode-request`(msg) 均**非必需**（P9/P19/P15）。
5. 错误文案 "free tier can only be used from within OpenCode" 有误导性——它只是"UA 或 session 结构未过"的兜底错误，**不是**客户端真实性验证。
6. 仍有不可穷尽项（闭源网关内部限流/配额参数、URL/model 值未作变量等），见 §7；body 维度已于 2026-09-22 补测（门③，见 §5.2）。
7. 2026-09-22 晚 G/H 系列（aicli 接入判别）在 P/T 之外另发现**门⑤（完整身份头组）**、**门⑥（工具面白名单 ≥2 个真实 schema）**与 **reasoning_effort 值域**，并把门③ 适用场景收窄（详见 §5.3、请求参数文档 §3.3）。

## 1. 客户端：ID 生成算法

### 1.1 源码位置

```text
packages/opencode/src/session/session.ts     # 创建会话时生成 ID（约 :513）
packages/schema/src/session-id.ts            # ses_ ID 类型定义
packages/schema/src/identifier.ts            # 核心生成算法
packages/opencode/src/session/llm/request.ts # msg ID（input.user.id）用于 header 注入
```

### 1.2 算法

```text
ID = 前缀 + 时间部分(12位hex) + 随机部分(14位base62)   // 共 26 字符
```

1. **时间部分**：
   - `current = Date.now() * 0x1000n + 同毫秒计数器`（计数器在同一毫秒内递增；实测样本 counter=1）；
   - `ses_` 前缀用 **descending**：`value = ~current`（按位取反 → 新会话字典序更小，可倒序排列）；
   - `msg_` 前缀用 **ascending**：`value = current`（正序）；
   - 取 `value` 的**低 48 位** → **12 位小写 hex**。
2. **随机部分**：`crypto.randomBytes(14)`，每个字节 `b` 映射到 base62 字符集：

```text
CHARS = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"
rand[i] = CHARS[b % 62]
```

> 注：`b % 62` 存在轻微模偏差（256 % 62 ≠ 0），但这是实现原样，照抄即可。

### 1.3 复刻验证

复刻生成器（`scripts/probe-session.js` 中 `makeId()`）与真实数据对照：

- 用 `now - 2ms` 与 `now` 生成的两个 `ses_` 时间段 hex 差恰为 `0x2000`（= 2 × 4096），与算法预测逐位一致；
- 3.58 天前时间戳（`now - 86h`）正确落入 48 位时间段内，结构合法；
- 用复刻算法生成的 ID 全部通过服务端校验（P1/P2/P3/P15/P18~P22 等）；
- 抓包原始 ID 对解码回验：`ses_f3879bba0ffe…` → `2026-09-22T05:11:00.447Z`，`msg_0c786447b001…` → `05:11:00.475Z`——两者仅差 28ms（会话创建后随即产生首条消息），与"同一会话的消息 ID 正序紧随会话 ID"的语义吻合。

**结论：生成侧没有任何未知项。** `x-opencode-request` 头携带的 `msg_` ID 与 `x-opencode-session` 的 `ses_` ID 出自**同一算法**（`identifier.ts`），仅两处差异：前缀为 `msg_`、时间部分**正序不取反**（ascending）。服务端对该头无任何校验（P15 整头省略仍 200；早期隔离实验中"原始 session + 伪造 request ID"同样 200），因此它只用于服务端埋点/sticky/用量归属，不参与准入判定。

## 3. 判别实验方法

- **基座**：原样重放抓包得到的原始 2467B payload（`data/replay/muc7umlx-1qdmbboy.json`，模型 `mimo-v2.5-free`），POST 到 `https://opencode.ai/zen/v1/chat/completions`；
- **单变量**：每针只改动一个 header（session / UA / client / project / msg），其余保持原始值；
- **判定**：HTTP 状态 + 错误体（200=SSE 流正常返回 / 403 FreeTierError / 426 UpgradeRequired）；
- **基础 headers**（非 UA 探针恒定）：

```text
content-type: application/json
user-agent:   opencode/1.18.32 ai-sdk/provider-utils/4.0.23 runtime/bun/1.3.14
x-opencode-client: cli
x-opencode-project: global
```

早期隔离实验（同 payload）已确认：原始 session + 伪造 request ID → 200；伪造 session → 403——请求 ID 无作用，session 是唯一会话键。

## 5. 推断出的准入判定逻辑

### 5.1 伪代码（行为级等价刻画）

```js
// 闭源 Console 推理服务对匿名(Bearer public)免费额度请求的准入判定
function admit(headers) {
  // ① session 结构校验（优先执行，P23 证明）
  const ses = headers["x-opencode-session"]
  if (!/^ses_[0-9a-f]{12}[0-9A-Za-z]{14}$/.test(ses ?? ""))
    return [403, "FreeTierError",
            "OpenCode's free tier can only be used from within OpenCode"]

  // ② UA 版本校验：子串搜索 + 大小写不敏感（P22/P24），三段可缺省（P21）
  const m = /opencode\/(\d+)\.(\d+)(?:\.(\d+))?/i.exec(headers["user-agent"] ?? "")
  if (!m)
    return [403, "FreeTierError",
            "OpenCode's free tier can only be used from within OpenCode"]
  const version = [Number(m[1]), Number(m[2]), Number(m[3] ?? 0)]
  if (cmp(version, [1, 18, 0]) < 0)          // >= 1.18.0 闭区间（P17/P18）
    return [426, "UpgradeRequired",
            "OpenCode 1.18.0 or newer is required to use the free tier"]

  return "pass"   // → 网关转发至推理 provider
}
```

> 边界声明：正则是对 24 针实测行为的**最小等价刻画**，未证明服务端实现逐字符等同（见 §7）。

### 5.2 门③：body 形态（2026-09-22 T1~T11 单变量补充）

header 双门之外，body 也参与准入——**并列两条件，缺一 403**（大小无关、user 内容无关、temperature/stream_options 无关）：

| 条件 | 通过证据 | 拒绝证据 |
|---|---|---|
| A. `messages` 首条 system 含**真实 opencode 模板内容**（抓包 title-gen 2096B） | T1（原 payload 仅改 max_tokens）/T8（真模板+任意 user）→ 200 | T3 无 system、T4 短 system、T5 `x*3000`、T9 `y*2100` → 403（长度假设被 T5/T9 证伪） |
| B. `"stream": true` | T11（真模板+仅补 stream）→ 200 | T10（真模板但缺 stream/temperature/stream_options）→ 403 |

- 早期“准入只看 header”结论因此**收窄修正**：在固定 payload 下成立，换 body 即失效（原 §7② 已更新）；
- 工程落地：`proxy-go/fixup.go` 的 `inject_template` 模式——保序字节拼接注入 **role-first** 模板 + 强制 `stream:true`（直接 Go map 重序列化会把 key 变字母序/content 在前，实测 403，推测门③对原始字节/结构匹配）；非流式调用方由代理 SSE→JSON 组装回传，实测极简 body 经代理 → 200；
- 未穷尽：模板匹配是全等/前缀/标记（`<rules>` 等）未判别；真实 **agent 系统提示词**是否同样通过未测。

### 5.3 门⑤/门⑥ 与 reasoning_effort 值域（2026-09-22 晚 G/H 系列补充，aicli 接入判别）

> 场景：aicli 等**非 opencode 客户端**经本地代理调 `https://opencode.ai/zen/v1/chat/completions`（模型 `mimo-v2.6-flash-free`）遇 403/500。单变量实测（脚本 `scripts/experiments/replay/` 下的 `run-g-tests.py`、`run-h-*.py`、`run-precision*.py`、`run-effort-values*.py`；真实上游）定位到三道此前未覆盖的规则：

**门⑤：完整身份头组（先于 body 校验）**。不带 opencode 客户端身份头（UA `opencode/<ver>…` + `x-opencode-session`/`x-opencode-client`/`x-opencode-project`/`x-opencode-request`）→ **任何 body 一律 403**（G1/G2d/H1/H5 全 403）；带齐即放行（G6 两次复现 200）。值无需真实有效（proxy-go 注入的编造 session 值 T13 也过 200）。→ 现场 opencode TUI 200 即自带真头；P 系列"极简 body 经代理 → 200"与之一致（代理已注入身份头）。

**门⑥：工具面白名单（数量 ≥ 2 且 schema 须为 opencode 真实工具）**。aicli 自带 46 个工具 → 403（T12/H2/H4）；opencode 真实工具 schema **2 个即 200**（H17）、6 个 200（H15）、12 个 200（H13）；真实 schema **1 个 → 403**（H16）；1 个伪造最小 bash schema → 403（S4/T15）。→ 数量下界 = 2 个真实 schema。

**reasoning_effort 值域**（表见请求参数文档 §3.3）：`max`/`minimal`/`xhigh`/任意非法值 → 500；`none`/`low`/`medium`/`high`/缺省 → 200。协议角度该字段与 `max` 均合法（官方 SDK 类型为证），500 根因 = **取值超出该模型后端支持面**（后端只认旧四值）。修复 = **改值**（`max → "high"`/`"medium"`）而非删字段。

**门③ 适用场景收窄**：H13（aicli env-context system，**无** opencode 模板）+ 完整身份头 + 12 真工具 - effort → 200；H14 同 200。→ 带完整身份头组合下 **system 内容完全不参与准入**；早前把 system 模板判为必需（H-A）的证据只覆盖**不带完整身份头组合**的观测条件。代理 `inject_template` 逻辑仍成立（兼容该场景），但不再是唯一合规路径。

## 7. 未覆盖与不可知项

**① 可补测但未穷尽的边缘**（低优先）：

- 随机段字符逐一枚举（仅证 `[-]` 拒绝、`[0-9A-Za-z]` 通过样本，未逐一试 `_`/`!`/emoji 等）；

- 小写前缀 `ses_` + 时间段之外的组合边界（如前缀后多余字符）。

**② 实验设计中的常量（未作为变量）**：

- ~~body（2467B 原始 payload）~~ **已判别**（2026-09-22 T1~T11，见 §5.2）：system 模板内容 + `stream:true` 参与准入，“100% 由 header 解释”仅在固定 body 下成立；URL 路径 `/zen/v1/chat/completions`、模型 `mimo-v2.5-free`、`authorization: Bearer public` 仍全程恒定未单列。

- session 在服务端是否还参与 sticky 路由/遥测的生产行为（开源代码写了，线上未验证）；
- 是否存在未触发的其他分支（登录态、trial 状态相关错误）；
- 为何门槛设为 1.18.0（策略意图，非算法）。
